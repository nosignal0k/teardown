先落盘再执行 · 异常包成结果

深入

教学上把「再读今日文件」收成同一种往返。并行按钮只演示两个只读，不暗示两次写入互不冲突。需要代理状态的工具（短记忆、会话检索、委派、任务清单）由代理层处理，不走普通注册表。任务清单现在的名字是 todo_list，todo 只是旧名。

工具请求会先写入会话，再执行。用户取消模型请求，不会自动收回已经发生的写入或已经发出的消息。

固定版本安全表 · 检查代码

深入

危险命令检查的顺序，在这份代码里大致是：用户自己的拒绝规则和硬性底线先挡，容器后端可以跳过其后的危险命令提示，YOLO 或关闭审批也绕不过硬性底线。智能模式可以由辅助模型放过它认为低风险的命令。定时任务里的危险命令默认拒绝，这个默认可以改。

文件写入范围只限制 write_file 和 patch。终端、插件和 MCP 不因此被同一条线围住。页面不展示可复制的破坏性命令，也不真正删除任何东西。

默认原地压缩 · 同标签上的旧说法

深入

代码默认 compression.in_place 为真：在同一个会话 id 上改写要送出的消息，压缩前的内容软归档，仍可搜索，默认不新开子会话。同一标签里的 agent loop 文档仍写「超过 50% 就压缩」并且「生成 child session」。那是文档和代码不一致，主图不采用文档里的固定比例，也不画会话分裂。

配置里的起始比例是 0.50，但上下文窗口小于 512K 时，代码会把触发比例抬到至少 0.75，另外还有按模型覆盖。所以不能说每个模型到 50% 一定压缩。检索是 SQLite 的 FTS5 全文检索，不是默认的向量检索。摘要遗漏之后再搜，也不保证每次都找回。

新的任务会话 · 网关入口

深入

Gateway 是连接已配置消息平台的常驻进程：授权、会话键、跑一轮、再把文字送回去。定时任务由它或同一台主机上的调度触发。普通任务默认开一个新的会话，而不是把所有聊天历史接上。另有不调用模型、只跑脚本的模式。正在跑的定时任务默认不能再创建定时任务，避免无人看管时自己越排越多；这个限制是策略，配置可以打开。

主机没开、网关没在跑，就不会有成功结果。模型失败时，只有配置了备用提供者才会再试，而且仍可能失败。父代理和子代理各有自己的步数预算，不能把一边的上限当成整棵调用树的花费上限。这份代码里，主循环的步数默认不封顶，子代理的默认上限是 250。同标签的 agent loop 文档仍写 500 和 50，以代码为准。
